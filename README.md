# 时间上的中国

一个可拖拽浏览的中国历史时间轴网页应用，收录从古人类时期（约170万年前）到 1980 年的 104 个重大历史事件。

在线访问：https://plantatree2023.github.io/chinesehistory/

## 功能

- 页面正中为时间轴，可用鼠标 / 手指左右拖拽、滚轮、方向键或底部缩略条浏览（点击缩略条后也可用方向键、Home、End）；点击左上角标题回到时间轴开头（外观与普通标题相同）；到达两端时隐藏对应的翻页按钮；最早的时期之前留有一段渐隐的轴线
- 时期更迭事件在时间轴上用菱形标记（新时期的颜色）；时间轴到卡片的连线使用该事件所属时期的颜色
- 自动播放：页面加载后时间轴默认缓缓向右前进（约每 30 秒一屏）；手动浏览时暂停，停止操作约 3 秒后以原来的速度自动继续；右上角的播放按钮依次切换：播放（一倍速）→ 二倍速（双箭头图标，二倍速时按钮角上显示“2×”）→ 暂停，空格键直接播放 / 暂停；手动暂停后本次访问中不再自动继续，直到再次播放（从一倍速开始）；到达末端停止；系统设置了“减少动态效果”时不自动开始
- 背景音乐：音量较小、循环播放，页面加载后立即尝试播放；浏览器不允许操作前发声时，音乐按钮闪动几次提示（iPhone / iPad 上始终如此），访问者第一次点击、触摸或按键（任何位置）后开始；右上角的喇叭按钮可以关闭，并记住选择。每个数据集在 `music` 字段中配置自己的音乐（音频放在 `audio/`），没有配置则不显示音乐按钮
- 背景纹理：时间轴后面铺一层清淡的纹理（中国数据集为宣纸纤维），每个数据集在 `texture` 字段中配置自己的纹理（图片放在 `textures/`），深浅两种配色自动适配
- 事件卡片交错排列在轴线上下方，包含代表性图片与简要说明；图片大小按事件的重要程度（1–10）分三级：1–5 小、6–7 中、8–10 大（重大事件）；轴线按朝代着色，背景随时期颜色渐变（保留纸色主调）
- 为保持清爽，任意一屏宽度内最多显示 6 个事件；时间轴区域宽度不小于 1600px 的大屏幕上最多 8 个，避免大屏上留白过多（窗口大小变化时自动重新排版）
- 点击事件查看详细说明（≤600 字）和最多 9 张图片，调试模式下可编辑、删除
- 底部“浏览所有历史事件”按钮打开侧栏，按时间顺序列出全部事件，支持搜索；调试模式下可编辑、删除
- 侧栏可按**重大事件**（重要程度 8–10）、**时期更迭**（这两项为勾选框，排在最前）、**事件类型**（带颜色的下拉多选，如政治、战争、文化、科技）、**朝代 / 时期**（带颜色的下拉多选）和**时间范围**筛选，可与搜索同时使用；可选项由数据集决定（时期来自 `eras`，类型来自 `types`，年份范围来自事件）
- 详情和侧栏列表中显示事件类型（描边的类型色标签，与朝代的实心色块区分）；重要程度是内部信息，只在编辑页（调试模式）中显示和修改
- 右下角“+”按钮（悬浮在底栏上方）添加新事件（支持图片网址或本地上传，可为每张图片填写标题；调试模式下显示）
- 编辑页点击“保存”后按钮立即显示“保存中…”（本地文件模式下等待写入完成，失败时显示原因并可再次保存），完成后显示“✓ 已保存”再关闭
- **深色模式**：默认浅色（日间）；右上角的月亮 / 太阳按钮切换浅色与深色，记住选择（保存在当前浏览器中）
- **网址记录当前状态**，可以直接打开、刷新和分享：`?id=e052` 打开该事件的详情；`?browse` 打开侧栏，搜索词和筛选条件也写在网址中（如 `?browse&q=长城&major=1&type=war,culture&era=唐&from=-221&to=907`，类型使用 `key`）；`?at=755` 为时间轴中央的年份。打开详情、侧栏时新增一条浏览记录，浏览器的“返回”会先关闭它们；改筛选、拖动只更新当前网址。详情中有“分享链接”按钮（手机上调用系统分享，电脑上复制链接），打开详情时浏览器标题显示事件名
- **下拉刷新**：手机等触屏设备上向下拉动页面、松开即可刷新（横向拖动时间轴、侧栏或弹窗打开时不会触发）
- 每个事件可以有多条参考链接（可带标题），详情中逐条列出；编辑页可添加、修改、删除
- **调试模式**：侧栏底部的“调试模式”开关（只在本地 `npm start` 启动时显示，见下文），默认关闭，状态保存在当前浏览器中。开启后在顶栏下方显示网站最近更新时间和版本，右上角最左侧显示 GitHub 仓库按钮和“清除缓存并刷新”按钮（绕过浏览器缓存重新下载网页、代码、样式和数据后刷新，保存在浏览器中的修改和设置不受影响），并显示全部编辑功能（新增、编辑、删除、恢复默认数据）；关闭时这些编辑功能全部隐藏，其余功能不变
- 数据保存在 `data/<国家>_<语言>.json`：本地运行时修改直接写入该文件，线上浏览时修改保存在访问者自己的浏览器中（见下文）
- **反馈 / 建议修改**（所有访问者，不需要调试模式）：事件详情底部的“反馈 / 建议修改”按钮自动带上该事件，可选反馈类型（事实错误、错别字、图片有问题、链接失效、其他；图片问题可指出第几张图并建议图片网址），也可以“直接建议修改内容”——打开编辑页的建议模式，预填标题、时间、简要说明、详细说明、类型、参考链接，提交时只发送改动的字段及改前改后、一句说明和可选的联系方式（不修改网站数据，不开放图片上传）。侧栏底部的“反馈 / 建议新增事件”用于整站反馈和建议新增事件。反馈通过 [Web3Forms](https://web3forms.com) 发送到维护者邮箱，见下文“反馈设置”

## 反馈设置

反馈通过 Web3Forms 发送到维护者邮箱（免费额度每月 250 条）：

1. 在 https://web3forms.com 输入接收反馈的邮箱，获取 Access Key（会发到该邮箱）；
2. 把 Access Key 填入 `js/config.js` 的 `feedback.accessKey`，提交并部署。

Access Key 设计上就是公开写在网页中的（只能用来向该邮箱发送表单）。`accessKey` 为空时反馈入口照常显示，提交时提示“反馈服务尚未配置”；`enabled: false` 时不显示任何反馈入口。表单带有防垃圾的隐藏字段（`botcheck`）。

## 数据来源

事件文字摘自[中文维基百科](https://zh.wikipedia.org/)（CC BY-SA 4.0），图片来自[维基共享资源](https://commons.wikimedia.org/)，全部保存在 `images/` 目录，网站只从本地加载图片
（在无法访问维基百科的网络环境下也能正常显示），版权及许可以各文件在维基共享资源上的说明为准。

标题字体为[马善政毛笔楷书](https://fonts.google.com/specimen/Ma+Shan+Zheng)（SIL Open Font License 1.1），
只保留标题和朝代名用到的字（`css/fonts/`，约 16KB），许可证见 `css/fonts/OFL-MaShanZheng.txt`。
新增的时期名若含子集外的字，会自动回退为宋体显示。

## 本地运行与编辑数据

纯静态网站，无需构建。在项目目录运行：

```bash
npm start               # 启动本地服务 http://127.0.0.1:4173/（提供调试模式）
npm run start:public    # 同上，但不提供调试模式，看到的与线上一致（等同于 npm start -- --no-debug）
```

编辑功能只在**调试模式**下显示：打开“浏览所有历史事件”侧栏，打开底部的“调试模式”开关。
**“调试模式”开关只在本地启动时显示**：线上（GitHub Pages）和 `--no-debug` 时不显示，浏览器中保存的开启状态也不起作用。
原理：仓库中的 `js/env.js`（部署到线上的版本）为 `debugAvailable: false`，本地服务器默认改为返回 `true`。

**本地文件模式**：通过 `npm start` 访问时，在网页中新增、编辑、删除事件会直接写入 `data/cn_zh.json`，
上传的图片保存到 `images/`（以内容哈希命名）。确认无误后提交并推送，线上网站就会更新：

```bash
git add data images && git commit -m "更新历史事件" && git push
```

**编辑页添加图片**：可以上传图片，也可以粘贴图片网址。网址对应的图片会先下载到本地再加入，数据中不保存外部网址：
本地文件模式下由本地服务器下载并保存到 `images/`；浏览器模式下由浏览器下载（需要对方网站允许跨域下载，
例如维基共享资源），压缩后与上传的图片一样保存在当前浏览器中；不允许的网站会提示先保存到电脑再上传。

**浏览器模式**：在 GitHub Pages 等静态托管上没有写入接口，访问者的修改只保存在其浏览器的 localStorage 中（只保存改动过的字段和删除的事件，数据文件以后的更新对没有改动过的内容仍然生效），
不会影响仓库数据；侧栏底部可“恢复默认数据”。

**网站更新时间**：调试模式下顶栏下方显示“网站最近更新”的时间（按浏览器所在时区）和版本号，来自网站根目录的 `version.json`。
该文件由部署流程（`.github/workflows/deploy.yml`）在每次 push 到 `main` 时生成，记录部署时间、提交哈希和提交时间，不需要手工维护，也不提交到仓库；
本地运行时由 `server.js` 根据 git 最近一次提交生成（显示“本地”）。

## 从维基百科导入事件

`tools/wiki-import.js` 按关键词查询维基百科，新增或更新数据集中的条目：

```bash
npm run wiki -- --file data/cn_zh.json 淝水之战 北京奥运会      # 一个或多个关键词
npm run wiki -- --file data/cn_zh.json --list topics.txt         # 条目表，逐条查询
npm run wiki -- --file data/cn_zh.json --dry-run 北京奥运会      # 只显示将做的修改，不写文件
npm run wiki -- --file data/cn_zh.json --year 1997 香港回归      # 指定年份
npm run wiki -- --file data/cn_zh.json --refresh-images 淝水之战     # 用维基图片整组替换已有图片
npm run wiki -- --file data/cn_zh.json --type 战争 --score 6 淝水之战  # 指定类型和重要程度
```

- 条目表每行一个关键词，可写成 `关键词|年份|类型|重要程度`，后几项可省略或留空（公元前写负数；例如 `淝水之战|383|战争|6`、`淝水之战|||6`），`#` 开头为注释。
- 维基语言由文件名决定（`cn_zh.json` → 中文维基，简体）。关键词先按条目名查询，查不到再搜索；
  搜索到的条目须在简介中提到该关键词，否则视为找不到。
- **图片一律下载到本地**：维基图片（维基生成的缩略图，通常几十 KB）下载到数据文件上一级目录的 `images/`
  （`data/cn_zh.json` → `images/`），按内容哈希命名、同一张图只存一份，并记录宽高；单张下载失败时跳过并提示。
- **已存在的条目**（事件名与关键词相同，或对应同一维基条目）：更新详细说明等来自维基的内容；参考链接中同一维基站点的链接更新为当前条目地址（没有时加在最前面），其他链接保持不变；
  保留事件名、年份、简要说明、类型、重要程度等人工内容；指定了年份、类型或重要程度时以指定的为准。已有图片默认保留
  （没有图片的条目会从维基补上），加 `--refresh-images` 则用维基图片整组替换。
- **新条目**：事件名使用关键词；年份取自 Wikidata，取不到时从简介文字中查找（会提示核对），
  仍无法确定则报错，需要用 `关键词|年份` 或 `--year` 指定。
- **类型与重要程度**：新条目自动填写，已有条目缺少时补上（都会提示核对）。
  类型依次取自 Wikidata 的“性质”（如战役→战争、条约→对外交流、考古学文化→史前）、事件名中的关键词（如“之战”“条约”“发明”）、
  年代（前 2000 年以前为史前）、简介首句中的关键词；都无法判断时不填写并提示。用现有 100 个事件检验，仅凭关键词即有 94 个与人工分类一致。
  重要程度根据 Wikidata 中该条目的语言版本数估算（越多越受关注，范围 2–9），没有 Wikidata 时为 5。
  这只是粗略的参考：与人工评分相比约 57% 相差不超过 1，建议导入后核对，或用 `--score` / 条目表第四项直接指定。
- `--dry-run` 只显示将做的修改和将下载的图片数量，不下载、不写文件。
- 写入前按网站服务器的同一套规则校验数据；遇到维基限流会自动等待重试。

## 数据格式与多语言

每个数据集是一个 JSON 文件，命名为 `data/<国家>_<语言>.json`（如 `cn_zh.json`、`jp_ja.json`），包含时期划分 `eras`
和事件 `events`；通过网址参数切换：`?data=jp_ja`，默认 `cn_zh`。所有字段的含义与规则见 [`data/README.md`](data/README.md)。

## 测试

使用 [Playwright](https://playwright.dev/) 在 Chromium 中做端到端测试，全程离线（外部图片请求会被屏蔽）。每次改动后运行：

```bash
npm install                      # 首次运行需要
npx playwright install chromium  # 首次运行需要（已安装浏览器可跳过）
npm test                         # 自动启动本地服务并运行全部测试
npm run test:report              # 查看上次的 HTML 报告（失败时含截图与操作记录）
```

## 目录结构

- `index.html` 页面结构
- `css/style.css` 样式
- `js/app.js` 交互逻辑
- `js/config.js` 网站配置（反馈服务的 Access Key）
- `js/env.js` 运行环境：线上不提供调试模式，本地服务器改为提供
- `js/vendor/` 第三方库（微信分享二维码 qrcodejs，MIT），保存在本地，`async` 加载不阻塞页面
- `data/<国家>_<语言>.json` 数据集（事件与时期划分），字段说明见 `data/README.md`
- `images/` 事件图片（网站只从这里加载图片）
- `audio/` 背景音乐（各数据集在 `music` 字段中引用）
- `textures/` 背景纹理（各数据集在 `texture` 字段中引用）
- `server.js` 本地服务器（静态文件 + 本地文件模式的写入接口 + 本地的 `version.json`）
- `lib/images.js` 图片工具（识别格式与尺寸、下载、按内容哈希保存），服务器和导入脚本共用
- `tools/wiki-import.js` 从维基百科导入 / 更新事件的命令行脚本
- `tests/` 自动化测试（`helpers.js` 为共用工具）
