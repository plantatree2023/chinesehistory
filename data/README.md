# 数据集说明

本目录存放时间轴的数据集。每个数据集是一个 JSON 文件，包含该国的**时期划分**（`eras`）和**历史事件**（`events`）。
网站、本地服务器（`server.js`）、维基导入脚本（`tools/wiki-import.js`）和测试都读写这里的文件。

## 文件命名

```
data/<国家>_<语言>.json
```

| 部分 | 规则 | 例 |
|---|---|---|
| 国家 | ISO 3166-1 两位小写字母代码 | `cn` 中国、`jp` 日本 |
| 语言 | ISO 639 两到三位小写字母代码，可附加文字变体（`-` 后 2–8 位字母或数字） | `zh`、`en`、`zh-Hant` |

例：`cn_zh.json`（中国 · 中文，默认数据集）、`jp_ja.json`（日本 · 日文）、`cn_en.json`（中国 · 英文）。

- 网站通过网址参数选择数据集：`?data=jp_ja`；不带参数时使用 `cn_zh`。
- 维基导入脚本根据文件名决定查询哪种语言的维基百科（`cn_zh.json` → 中文维基，简体）。
- 名称不符合上述格式的文件不会被网站加载，服务器也拒绝写入。

## 整体结构

```json
{
  "id": "cn_zh",
  "country": "cn",
  "language": "zh",
  "eras": [ { "name": "唐", "start": 618, "end": 907, "...": "..." } ],
  "events": [ { "id": "e052", "year": 755, "title": "安史之乱", "...": "..." } ]
}
```

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `id` | 字符串 | 是 | 数据集名称，**必须与文件名（去掉 `.json`）完全一致**，例如 `cn_zh`。服务器保存时会核对。 |
| `country` | 字符串 | 是 | 国家代码，与文件名中的国家部分一致，例如 `cn`。 |
| `language` | 字符串 | 是 | 语言代码，与文件名中的语言部分一致，例如 `zh`。 |
| `eras` | 数组 | 是 | 时期划分，见下文。 |
| `events` | 数组 | 是 | 历史事件，见下文。 |

## 时期（`eras`）

时期决定时间轴上的朝代色带、悬浮 / 点击时间轴时的时期提示、顶栏标题后的当前时期名和下沿色条、底部进度条的分段，以及侧栏“朝代 / 时期”筛选的选项（只列出有事件的时期）。

```json
{ "name": "唐", "start": 618, "end": 907, "color": "#c0892f", "range": "618年—907年", "desc": "国力强盛、文化繁荣的开放王朝" }
```

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `name` | 字符串 | 是 | 时期名称，显示在色带上、时期提示、顶栏和进度条标签中。 |
| `start` | 整数 | 是 | 起始年份（公元纪年，公元前为负数），用于判断某一年属于哪个时期。 |
| `end` | 整数或 `null` | 是 | 结束年份，用于绘制色带的右端。**`null` 表示延续至今**：色带一直画到时间轴末端（“今天”刻度）。 |
| `color` | 字符串 | 是 | 十六进制颜色（如 `#c0892f`），用于色带、进度条色段、顶栏下沿色条和标题中的时期名。 |
| `range` | 字符串 | 是 | 显示用的起止年代文字，出现在时期提示中，例如 `约前2070年—前1600年`、`1949年至今`。可以与 `start` / `end` 不完全一致（例如史学上有争议的年代写“约”）。 |
| `desc` | 字符串 | 是 | 一句话简介，出现在时期提示中。 |

规则：

- 按 `start` 从早到晚排列。某一年属于**起始年份不晚于它的最后一个时期**，因此时期之间不要有空档；重叠时后面的时期优先。
- 第一个时期的 `start` 应早于最早的事件。
- 顶栏标题使用书法字体，字体文件只包含标题和现有时期名用到的字；新时期名若含其他字，会回退为宋体显示（见仓库根目录 README）。

## 事件（`events`）

每个事件对应时间轴上的一张卡片。文件中的事件按 `year` 排序（网站和导入脚本写入时会自动排序），便于查看 git diff。

```json
{
  "id": "e052",
  "year": 755,
  "date": "755年",
  "title": "安史之乱",
  "short": "节度使安禄山与史思明起兵叛乱，历时七年多，唐朝由此由盛转衰。",
  "detail": "安史之乱（755年12月16日－763年2月17日）是中国唐中期爆发的一场大规模内战……",
  "images": [
    { "src": "images/1f0e3c9a7b2d4e5f.jpg", "w": 500, "h": 375, "caption": "安禄山像" }
  ],
  "source": "https://zh.wikipedia.org/wiki/%E5%AE%89%E5%8F%B2%E4%B9%8B%E4%BA%82",
  "major": false
}
```

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `id` | 字符串 | 是 | 事件的唯一标识，**数据集内不能重复**。初始数据为 `e001`–`e100`；导入脚本新增时取下一个编号（`e101`……）；在网页中新增的事件使用自动生成的随机标识。修改事件时不要改动。 |
| `year` | 整数 | 是 | 事件年份，公元纪年，**公元前为负数**（公元前 221 年写 `-221`），没有公元 0 年。决定事件在时间轴上的位置、排序、所属时期，以及侧栏“时间范围”筛选的上下限。远古事件可以写很大的负数（约 170 万年前写 `-1700000`）。 |
| `date` | 字符串 | 是 | 卡片和详情中显示的时间文字，可以比 `year` 更灵活，例如 `约前2070年`、`传说时代`、`北宋末年`、`493年起`。在网页中新增事件时若留空，会按年份自动生成（如 `公元前221年`）。 |
| `title` | 字符串 | 是 | 事件名称，不能为空。网页编辑器限制 40 字。维基导入时使用输入的关键词。 |
| `short` | 字符串 | 是 | 简要说明，显示在时间轴卡片上。**至少 20 字（不计标点）**，网页编辑器限制 60 字。不足 20 字时卡片会自动从 `detail` 截取补足，但建议直接写足。 |
| `detail` | 字符串 | 是 | 详细说明，点击卡片后在详情中显示，**不超过 350 字**。可以包含换行。 |
| `images` | 数组 | 是 | 图片，**最多 9 张**，可以为空数组。**第一张为代表图**，按原比例完整显示在时间轴卡片上；其余在详情中以图集显示。没有图片的事件显示首字占位图。每张图片的字段见下表。 |
| `source` | 字符串 | 否 | 资料来源链接，显示在详情底部。维基百科链接显示为“维基百科”，其他链接显示原网址。可以为空字符串。 |
| `major` | 布尔 | 否 | 是否为重大事件。为 `true` 时时间轴上使用更大的卡片，并可用侧栏的“只看重大事件”筛选（数据中没有重大事件时不显示该筛选）。缺省视为 `false`。 |
| `wiki` | 字符串 | 否 | 对应的维基百科条目名，由维基导入脚本写入，用于再次导入时识别同一事件。网站不使用该字段。 |

### 图片（`images` 中的每一项）

**所有图片都保存在仓库的 `images/` 目录，网站只从本地加载图片，不引用任何外部地址。**

| 字段 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `src` | 字符串 | 是 | 图片路径，**只能是 `images/<文件名>` 形式**（文件名由字母、数字、`.`、`_`、`-` 组成）。外部网址、`data:` 内嵌图片或其他目录都会被服务器拒绝。新下载或上传的图片以内容的 SHA-256 哈希前 16 位命名（如 `images/1f0e3c9a7b2d4e5f.jpg`），同一张图片只保存一份，可以被多个事件共用。 |
| `w` | 整数 | 建议 | 图片宽度（像素），**必须与文件实际尺寸一致**。时间轴按 `w / h` 预先计算卡片形状，使代表图按原比例完整显示；缺少时网页会在图片加载后测量并重新排版。 |
| `h` | 整数 | 建议 | 图片高度（像素），要求同 `w`。 |
| `caption` | 字符串 | 否 | 图注，显示在图片查看器中，可以为空字符串。 |

图片格式为 JPEG、PNG、GIF 或 WebP。

## 如何修改数据

- **网页编辑**：在项目目录运行 `npm start`，打开 http://127.0.0.1:4173/ ，在网页中新增、编辑、删除事件会直接写回本文件；上传的图片和通过网址添加的图片都会保存到 `images/`（网址图片由本地服务器下载，数据中只记录本地路径）。
- **从维基百科导入**：`npm run wiki -- --file data/cn_zh.json 关键词`，会查询维基百科、下载图片并新增或更新事件（用法见仓库根目录 README）。
- **手工编辑**：直接修改 JSON 时，新图片需先放入 `images/` 并填写正确的 `w`、`h`。

无论哪种方式，提交前都要运行 `npm test`：测试会检查所有图片都是 `images/` 下存在的文件、尺寸与记录一致，以及排版规则等。

## 服务器保存时的校验

本地服务器（`npm start`）和导入脚本写入前会用同一套规则校验（`server.js` 中的 `validateDataset`），不通过则拒绝写入、原文件保持不变：

- `id` 与文件名一致，`eras` 和 `events` 都是数组；
- 每个事件是对象，`id` 为非空字符串且不重复，`title` 非空，`year` 为数字；
- `images` 是最多 9 项的数组，每项都有 `src`，且 `src` 必须是 `images/` 下的本地文件路径。
